# Work Package B Formal Model Training Protocol

## Purpose

Work Package B is responsible for converting Work Package A prepared data into
auditable `bc.risk-frame.v2` products that Work Package C can consume.  Model
training is allowed only when it preserves that contract: every training sample
must have an explicit route identity, grid identity, generation, input valid
time, target valid time, and forecast horizon.

The delivered legacy CNN is therefore kept frozen as
`experimental_unverified`.  It may remain as an optional research asset, but it
is not the formal B model and it must not be used to populate the production
RiskFrame/store path until it has independent time-aware validation evidence.

## Formal Training Input

The formal training source is a sequence of B `RiskFrame` objects generated by
`RiskBuildService`.  Each frame must contain:

- `risk_score`
- `risk_level`
- `hard_mask`
- `confidence`
- `environment_speed_factor`
- `latitude` and `longitude` coordinates
- route/run/scenario/corridor/vessel identities
- `generation_id`
- `model_config_digest`
- UTC `valid_time`

Unknown cells remain masked or NaN.  They are not silently converted to zero.
This keeps the training data aligned with the B fail-closed policy and avoids
teaching a model that missing information means low risk.

## Forecast Target

The first formal training protocol uses one-hour-ahead samples:

```text
input  = RiskFrame(valid_time = T)
target = RiskFrame(valid_time = T + 1 hour)
```

This directly addresses the audit concern that the old CNN had an undefined
`next-step` horizon.  Multi-hour products such as 6 h, 24 h, 72 h or total-voyage
risk must either be trained as their own supervised targets or evaluated through
a separate rolling strategy.  A one-hour model must not be copied repeatedly and
presented as a validated long-range forecast.

## Code Entry Points

The protocol is implemented in:

```text
src/arctic_route_risk/modeling/training.py
```

Key functions:

- `build_one_hour_training_samples(frames)`: converts adjacent formal risk
  frames into explicit supervised samples.
- `temporal_holdout_split(samples)`: creates a deterministic time-ordered
  train/validation split.
- `evaluate_persistence_baseline(samples)`: evaluates the simple baseline where
  the next risk equals the current risk.
- `summarize_training_readiness(samples, split)`: reports whether the data is
  sufficient for formal model training.
- `iter_training_sample_documents(samples)`: emits lightweight metadata records
  for audit manifests.

## Minimum Readiness Rule

The default readiness gate is intentionally conservative:

- at least 168 adjacent one-hour samples;
- at least 24 temporal holdout validation samples;
- a single explicit forecast horizon of 60 minutes;
- stable route/run/scenario/corridor/vessel/config identity inside each sample
  pair;
- validation data occurs after training data in time.

The threshold can be raised by competition policy.  Passing the readiness check
does not automatically promote a neural network.  It only means the training
dataset is organized enough for a model to be trained and evaluated.

## Relationship to the Legacy CNN

The legacy CNN asset has these limitations:

- it was trained on only 74 adjacent samples;
- its step length was not recorded as a formal time coordinate;
- it lacks source NetCDF hashes, validation split, test split, random seed,
  Torch version and training-code hash;
- its upstream license is not provided;
- it consumes a single old `comprehensive_risk` channel rather than the formal
  A-to-B input set;
- its output lacks `issue_time`, `valid_time`, `generation_id`, hard mask,
  confidence and C-ready identity fields.

For these reasons, it remains an optional experimental sidecar and is not part
of the official B-to-C handoff.  The formal path remains the audited RiskFrame
pipeline.

## Handoff to Work Package C

Work Package C should consume B outputs through the normal `RiskFrame` contract
and store interface.  Training artifacts and experimental models must not change
the C-facing schema.  If a future trained model is promoted, it must still
publish the same C-ready fields:

- `risk_score`
- `risk_level`
- `hard_mask`
- `confidence`
- `environment_speed_factor`
- route and scenario identities
- UTC issue/valid time metadata
- source/provenance summary

This keeps C stable while B improves its internal prediction method.
